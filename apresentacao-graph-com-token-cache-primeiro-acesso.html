2. E-mail — primeiro acesso e carga inicial

Esse fluxo responde à pergunta: “O que acontece quando o usuário utiliza a integração pela primeira vez?”

  1. O usuário autentica no CRM.
  2. O Front envia o access token para o backend.
  3. A Lambda consulta os e-mails na Microsoft Graph.
  4. Realiza paginação quando necessário.
  5. Aplica regras de negócio e monta a resposta.
  6. Salva os e-mails coletados no S3 Stage.
  7. Cria a Subscription para futuras notificações.
Rotas e permissões deste fluxo
PassoRota na Microsoft GraphPermissão delegada
Consulta os e-mails GET /me/messages?$top=&$select=&$orderby=receivedDateTime desc Mail.Read
Realiza paginação segue a URL de @odata.nextLink Mail.Read
Cria a Subscription POST /subscriptions
resource: /me/mailFolders('inbox')/messages		 Mail.Read

Ponto-chave: a carga inicial acontece uma vez. Depois disso, o fluxo normal passa a ser incremental.

3. Transcrições — carga inicial e notificações

3.1 Primeiro acesso / carga inicial

  1. O usuário autentica no CRM.
  2. O Front envia o access token para o backend.
  3. A Lambda utiliza MSAL para trabalhar com o token delegado.
  4. Consulta as reuniões do período e recupera as transcrições já disponíveis.
  5. Aplica as regras de negócio e salva as transcrições no S3 Stage.
  6. Cria uma Subscription para users/{userId}/onlineMeetings/getAllTranscripts.
Rotas e permissões deste fluxo
PassoRota na Microsoft GraphPermissão delegada
Consulta as reuniões do período GET /me/events?$filter=start/dateTime ge {inicio} Calendars.Read
Lista as transcrições da reunião GET /users/{userId}/onlineMeetings/{meetingId}/transcripts OnlineMeetingTranscript.Read.All
Baixa o conteúdo da transcrição GET /users/{userId}/onlineMeetings/{meetingId}/transcripts/{id}/content?$format=text/vtt OnlineMeetingTranscript.Read.All
Cria a Subscription POST /subscriptions
resource: users/{userId}/onlineMeetings/getAllTranscripts		 OnlineMeetingTranscript.Read.All

3.2 Nova transcrição disponível

Depois que a Subscription está criada, não é necessário ficar consultando o calendário continuamente para descobrir se uma nova transcrição apareceu.

  1. A transcrição fica disponível após a reunião.
  2. A Microsoft Graph envia uma Change Notification para o webhook.
  3. A Lambda identifica a Subscription e o usuário.
  4. Utiliza MSAL para obter um access token válido.
  5. Consulta o transcript/conteúdo correspondente na Microsoft Graph.
  6. Aplica regras de negócio e salva a nova transcrição no S3 Stage.
Rotas e permissões deste fluxo
PassoRota na Microsoft GraphPermissão delegada
Recebe a Change Notification a Graph chama o webhook exposto no API Gateway nenhuma
Consulta o transcript notificado GET /users/{userId}/onlineMeetings/{meetingId}/transcripts/{id} OnlineMeetingTranscript.Read.All
Baixa o conteúdo da transcrição GET /users/{userId}/onlineMeetings/{meetingId}/transcripts/{id}/content?$format=text/vtt OnlineMeetingTranscript.Read.All

4. E-mail — sincronização incremental

Esse é o fluxo normal depois do onboarding. A Subscription funciona como aviso; a Delta Query recupera somente as mudanças.

  1. Um novo e-mail chega na caixa do usuário.
  2. A Microsoft Graph envia uma Change Notification.
  3. A Lambda identifica a Subscription e o usuário.
  4. O MSAL recupera o contexto necessário para chamar a Graph.
  5. A Lambda executa a Delta Query.
  6. Somente alterações desde a última sincronização são processadas.
  7. Os novos dados são salvos no S3.
Rotas e permissões deste fluxo
PassoRota na Microsoft GraphPermissão delegada
Recebe a Change Notification a Graph chama o webhook exposto no API Gateway nenhuma
Executa a Delta Query GET /me/mailFolders/{folderId}/messages/delta Mail.Read
Continua a sincronização segue @odata.nextLink e guarda o @odata.deltaLink final Mail.Read
